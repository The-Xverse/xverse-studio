# ADR-0059 — Installed-provider campaign parameter mapping

Date: 2026-11-04. Status: implementation and verification in progress.

Extend finite campaigns through an installed provider's closed, frozen parameter
contract and pure source mapping. The common campaign service contains no industry
dispatch. A provider's availability or ordinary Start capability alone confers no
campaign mapping. The originally ready canonical base, current provider identity,
full compiled source and exact configuration remain required. Historical snapshots
without the contract remain unsupported.

The classic provider becomes 0.4.0 and admits only integer `durationSeconds` from
30 through 1800 seconds, concurrency one, on its existing complete-demo source.
Its worker already applies this setting. Seed axes remain unsupported because the
external runtime has no admitted applied-seed mechanism. Platform mode remains
unavailable for campaigns. Existing 0.3.0 assessment and 0.2.0/0.3.0 timeline
recordings remain readable through explicit version admission; their source clock
and event coverage semantics are unchanged.

The provider mapping changes only its admitted Scenario setting, preserving every
other source payload. Children receive new snapshots and server-owned lineage;
full project contributors, selection, profile identities and authoritative plan
are frozen again. Normal preflight computes actual diagnostics and readiness.
No synthesized ready preflight admits a child. Start repeats mutable admission,
exclusive installation checks and original owner verification. Unknown children
occupy their slot and are reconciled only from durable Start acknowledgement;
no restart uses Start to discover whether a previous dispatch occurred.

Preview remains side-effect-free and reports finite cardinality/budgets. The
contract declares its time parameter, bounds and seed policy. Request axes and
values must fit it before allocation. Unchanged accepted retries resolve their
original identities before new mutable admission. Existing reference campaign
behaviour remains separately scoped; no reference workload substitutes for the
current Autoverse verification target.

Verify unsupported historical sources/axes/seeds, strict bounds, immutable child
snapshots, full re-admission and exact retry identity first. Actual complete-demo
children, cancellation and native restart/reconciliation still require live
verification in the newly prepared isolated environment. T089/T090 and AC-028
remain open until their complete clauses have evidence. Windows remains unverified
under the latest supplied AGENTS instructions.
