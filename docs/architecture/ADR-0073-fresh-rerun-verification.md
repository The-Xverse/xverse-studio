# ADR-0073 — Fresh installation source and rerun verification

Date: 2026-11-05. Status: scoped contributor verification amendment.
Traces: T091; existing frozen-rerun and comparison-evidence admission contracts.

The reboot invalidated the old prepared namespace. Fresh private entry, display,
overlay and enrollment retain the SDK,92 regular pinned files, Zenoh binary,
container IDs/images/names and compiled container artifacts. The operator Docker
wrapper now selects the fresh private endpoint. All three exact container
configuration fingerprints differ only by observed HostConfig.Dns null versus
empty lists: substituting null in audit copies reproduces each old fingerprint.
No actual Docker configuration, historical receipt or fingerprint was normalized.
A new exact installation identity is recorded after current verification.

The mandatory frozen-rerun installation-identity guard stays unchanged. Historical
snapshots cannot execute under the new identity. A complete fresh two-child source
campaign therefore establishes compatible inputs before the actual rerun. Both
children demonstrate Android/APK, vehicle speed, canonical integrity and owned
cleanup. A captured isolated ADB helper is closed separately after proving its
original identity, private network and empty device list; the initial pending
observer result remains retained.

The first actual rerun reaches Android/speed and stops with complete cleanup, but
its contributor verifier then expects a different provider identity. That fixture
assumed source0.3 versus implementation0.4; the fresh source and rerun both use0.4.
Derive the expected same/different relation from the actual frozen identities and
assert both reported sides equal those identities. Parameters must still be same.
Keep the incompatible-result/fresh-admission assertions. The legacy missing-payload
diagnostic is replaced by the current explicit COMPARISON_EVIDENCE_UNSUPPORTED
contract (ADR-0066): existing receipts do not admit comparable numeric quantities.
All unrelated native execution, idempotency, immutable-input and cleanup assertions
remain unchanged. No production code, permission or comparison semantics change.

Preparation qualifications remain separate: the component Python contract uses-E
with its pinned user-site SDK; an isolated-I window probe cannot import pygame.
Old private middleware scratch is retained by whole-directory rename with observed
inode/metadata/readable-byte checks; unreadable files are not adopted or deleted.
Native clients use a new temp root at the existing two container bind-source path;
the private X server keeps a separate temp root with shared authenticated sockets.
The stopped Score archive API verifies exact native marker bytes. The stopped
bridge archive probe is unavailable due to a rootless read-only remount refusal;
actual bridge/vehicle runtime verification remains necessary and is distinct.

Repeat the complete actual rerun after this verifier repair, retain the first
failed verifier result, and audit all original T091 clauses before any task closure.
No Windows work, physical effects, deterministic replay, numeric clock/signal
admission, full acceptance or milestone claim follows from this amendment.
