# ADR-0003: Owned native reference and bounded evidence

Status: implemented reference scope; native Windows admission remains pending actual execution.

The current Lite public baseline cannot establish requested/effective input equality through an
admitted external runtime path. Studio therefore keeps that integration unavailable and supplies an
owned first-order model solely for core conformance. The model's declarative artifact identity and
bounded parameters are authored through the normal platform-admitted experiment profile. Both industry
examples use that same model/core; their terms do not imply domain fidelity or independent live providers.

The backend persists an idempotent operation, immutable source snapshot and exact launch authority
before effects. The provider recompiles those bytes using the pinned public XDL library and rejects
an effective-configuration/plan mismatch before model execution. Native subprocess argv contains only
an installed fixed module and backend-owned directory. Ownership recovery binds the secret digest,
creation identity and exact persisted invocation; uncertainty is preserved without replay or PID guesses.
A browser reconnect only reads state/events. Lifecycle, cleanup, evidence and assertion verdicts remain
separate. Linux process verification is actual; Windows requires its own native lane.

The owned provider journals original observations in a hash chain with a final digest. It does not
pretend to be admitted Argus, native X-COM, CARLA or physical evidence. Derived projections are
read-only, and evaluations use original evidence plus the admitted versioned pure JSON AST profile.
Imported reports are inert and convey no execution authority or producer authentication.

The required retained-history workload contains 50,000 events. The initial 16 MiB reader cap rejected
that workload; the retained failure is `evidence/studio/M1-review/history-before.json`. The successor
admits at most 64 MiB/100,000 canonical records, pages at most 200, and caches at most two verified
projections with at most 64 MiB contributing source bytes. Cache identity includes native file identity,
size/change timestamps and the expected digest; a source change forces re-verification. Invalid evidence
is not upgraded by a projection cache. This accommodates the existing workload without changing its
correctness or timing target. Browser rendering and Windows performance remain separately measured.

Compatibility impact: no existing XDL semantic rule or requirement ID changes. Reference-provider and
evaluator identities/limits are explicit capabilities. Unsupported semantics, physical coupling, feedback
compiler gaps and external integration remain open rather than receiving alternate invented behaviour.
