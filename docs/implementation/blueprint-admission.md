# Blueprint admission and two-domain boundary

`reference-process-control` and `reference-automotive` are Studio-owned blueprint bundles. Their exact
XDL is generated by `xverse_studio.xdl.examples.reference_resources`, supplied to the installed public
platform validator/compiler, and frozen for every run. Domain names/descriptions live in blueprint
metadata. The shared reference configuration mapper has no automotive/process conditional.

Both bundles execute the same finite normalized scalar response. This is useful for native
installation, editing, preflight, run ownership, failure markers, assessment, campaigns and evidence
exchange. It is not independent industrial process fidelity or automotive simulator evidence.
The exact MODEL_CONTRACT and its SHA-256 artifact identity are in the blueprint module; only the
declared parameters, fixed topology, deployment and observation contract are admitted by this
provider. Extra executable topology, schedules, targets, unknown extensions or unsupported edits
reject rather than silently running the original preset. Worker-side recompilation verifies effective
identities again before effects.

The assessment Profile `io.xverse.studio.experiments` v1.0 contains inert bounded definitions at a
Scenario-root extension point. Its exact local schema and Profile resource are admitted by the
platform's public `profile_schema_paths` mechanism, and the payload remains part of the full compiled
semantic identity. Definitions are separate consumers of evidence; allowing a definition edit does
not grant new provider execution capabilities. Unknown profiles and opaque expression strings do not
automatically become executable assertions.

not complete FR-046/AC-020's missing independent live two-industry acceptance.
