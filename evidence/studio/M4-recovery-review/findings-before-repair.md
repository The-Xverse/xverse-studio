## PRJ-IO-I01 — transient ancestor link can substitute external bytes in project reads (HIGH)

Exact pre-repair source identity and result are retained in projects-ancestor-before-repair.json; projects_ancestor_probe.py is reproducible. Projects._read_file first checks containment/ancestor links and then opens the complete path with leaf O_NOFOLLOW. At that final os.open, the probe temporarily renames the containing directory and substitutes an external owned-fixture directory link, restoring the directory immediately after open. The leaf is a regular file in the external directory, so O_NOFOLLOW does not reject it. _read_file returns the external sentinel bytes successfully, while the original project source and external fixture are both restored/unchanged.

The current checks do not anchor the directory chain used by the read. Reuse the host safe-I/O helper once independently reviewed, with descriptor-relative anchored ancestors and fail-closed unsupported platforms/identities. Bounded reads and source identity checks must remain intact. Add direct-reader and authenticated project-read regression cases, plus supporting-sidecar coverage, proving the external sentinel cannot be returned even if the ancestor name is switched only during acquisition. Root owns Projects repairs; reviewer makes no product changes.

## REC-IO-I02 — SQLite source acquisition can return a valid backup of an outside database (HIGH)

Exact source identity and two owned-fixture probes are retained in sqlite-ancestor-before-repair.json; sqlite_ancestor_probes.py is reproducible. On the second source SQLite connection (after initial source validation/inventory), temporarily substitute the source root with an outside fixture directory link during sqlite3.connect, then restore it immediately after acquisition. backup_full returns integrity=valid but its database contains outside-fixture instead of owned-source, while the original source database still contains owned-source. An anchored hash/copy-only repair would leave this SQLite C-extension reopen exposed.

Source and SQLite staging/destination acquisition require the same directory anchoring/identity guarantees, including any URI-based reopen; stopped-root WAL semantics must survive the chosen mechanism. The destination-acquisition probe on this baseline returned a SQLite disk I/O error with the outside fixture unchanged; no outside mutation is claimed from that case. All fixtures were newly owned loop10 data and were removed after the probe.

## REC-IO-I03 — locked root identity is not retained by subsequent safe reads (HIGH)

On the anchored-I/O successor, root-replacement-before-repair.json records backup_full returning integrity=valid with foreign-fixture in the backup database. The probe first allows capture/locking of the original source root. At the next source directory descriptor acquisition, it temporarily renames that root aside and renames a compatible owned foreign fixture directory into the selected source pathname (no symlink), then restores both after directory open. Helpers correctly anchor each individual acquisition, but they reopen from `/` rather than retain the already locked root descriptor. The later open therefore acquires the foreign root, validates its own files and produces a valid backup of the wrong root. Original and foreign database bytes remain unchanged.

This is a continuity issue distinct from symlink refusal: the user selected one stopped data root and the ownership lock covers that original root identity. Snapshot input acquisition must remain relative to that held root object, or reject before using a differing root identity. Apply the same reasoning to verification/restore input, reserved output and private SQLite staging identities; per-open safe path traversal alone does not establish operation-wide ownership continuity. Probe: recovery_root_replacement_probe.py; exact source digests retained in JSON. Root requested the independent continuity check. Reviewer makes no product changes.

## REC-IO-I04 — restore can report success after the requested output names a different root (MEDIUM)

On frozen recovery 1dc6ce8c / helper f5c5798c, output-binding-before-repair.json records the exact permanent-namespace probes. The backup variant refuses, but the restore variant returns status=restored, integrity=valid after an actual hook permanently renames the reserved output directory aside and moves a separate owned foreign fixture into the requested pathname during final .recovery-incomplete unlink. The newly restored database exists only in held-output, the requested output has no database, and held-output has had its incomplete marker removed. Foreign fixture bytes are unchanged.

A successful restore must still identify its reserved output at the requested name. Verify the final output binding before successful return and marker finalization; if a late mismatch is observed after marker unlink, preserve/recreate the incomplete marker through the retained owned anchor rather than claim a completed restore. No check can prevent an administrator moving files after operation completion, but this probe performs the move during the operation's own final side effect. Reproducible output_binding_probe.py uses only owned loop10 directories and requires hookExecuted=true. Reviewer makes no product changes.
