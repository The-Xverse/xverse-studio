# Anchored acquisition successor (Linux)

The original independent findings remain in `../independent-review.md` and `../../M4-recovery-review/findings-before-repair.md`; they are not overwritten by this successor. Author-added regression tests initially produced 3 failures and 1 pass against original recovery SHA919f777de8ed0ca48c8d68ca356c89de1b27f17c04c8c91b40535c5f83183f5e: transient parent substitution copied an outside owned-fixture payload, original-path SQLite reopening substituted an outside owned-fixture database, and the anchored helper did not exist. The original committed-WAL preservation fixture passed.

The successor walks every absolute directory component from the Linux filesystem root through no-follow directory descriptors. Source reads bind a regular singleton inode before opening and verify the opened descriptor, inode metadata, and its anchored name afterward. Targets are created exclusively through anchored parent descriptors, and permissions/fsync operate on descriptors. Arbitrary caller exceptions retain their identity.

Recovery acquires its ownership lock through an already opened data-root descriptor. It stages raw DB plus optional committed WAL through held source handles, then runs public SQLite backup only inside a private directory reached through a directory-descriptor URI. SQLite never connects to the original source path. Validation uses an anchored immutable file-descriptor URI. Restore stages outside the backup, clears sessions only in the staged restored database, retains the incomplete marker until success, and preserves source database/WAL bytes and other historical bytes. Private staging cleanup verifies directory identity and uses descriptor-relative removal.

`verification.json` records the exact candidate source hashes before/after and the command: 31 PASS, including two actual native Linux launcher recovery cases. No skips. This is author verification; independent successor review is separately owned by another agent. No Windows installation/tests, physical devices, or external providers were used. Hosts lacking the implemented Linux safe primitives return `RECOVERY_SECURE_IO_UNAVAILABLE`; safe native Windows acquisition remains held/unverified, and no shell/WSL fallback is used.

Before final closure, author review identified one additional acquisition precursor: `_root` still used `Path.resolve()` after preliminary symlink checks. A transient symlink during resolution could normalize a caller's original lexical path to another root before anchored acquisition. This was recorded before changing `_root`; successor removes resolution, rejects `..`, and leaves every actual directory acquisition to the anchored helper. Launcher canonicalization is separately reported to its owner. A subsequent exact-source receipt is required after this repair.

Independent reviewer subsequently reproduced REC-IO-I03: replacing the selected root with another ordinary directory after ownership-lock acquisition changed later fresh absolute-path reads to the foreign directory. This finding was recorded in the independent review before repair. The additional successor now retains operation-scoped directory identities: locked input root, verified backup input, reserved output, and each private staging root. All subsequent reads/writes/stat/inventory descend from those held descriptors, including SQLite staging. Directory acquisition also compares the named inode before opening with the opened descriptor. New regression hooks execute real ordinary-directory namespace replacement while opening the selected source database and creating the output manifest; the copied bytes remain from the locked root and outside fixtures remain unchanged.

The final author receipt is `verification.json`: **34 PASS**, exact source hashes unchanged, including the two actual native Linux cases. The earlier 32-case precursor receipt is preserved as `verification-before-root-continuity-repair.json` and does not establish closure of REC-IO-I03. Independent successor review is still required separately. No Windows checks were executed.

Before closure, author inspection of the final-name probe found a context-lifetime defect: private staging registered an anchor, then the outer operation registered the destination while staging was active. Exiting staging reset the entire ContextVar to its earlier token, removing the still-live output anchor. The permanent-name probe rejected rather than returning a false valid result, but later output acquisition could again walk the mutable destination name. This was recorded before repair. Scope cleanup must remove only its own anchor, preserving other active reservations even when scopes exit in a different registration order.

After preserving the output anchor correctly, the permanent-output-name probe confirmed the separate final-name issue: `output-name-after-scope-before-gate.json` returned valid while the requested path named the foreign directory (foreign bytes were unchanged; the valid backup was in the moved original directory). This result was recorded before repair. A final identity gate must compare the caller's still-named directory with the retained descriptor before reporting success, and before clearing a restore marker.

The independent reviewer then recorded REC-IO-I04 before repair: permanently replacing the restore target during the final anchored marker unlink caused a success response for a different visible path, while the moved owned root lacked its incomplete marker. The successor checks output directory identity before success and both before/after marker removal. On a late mismatch it recreates the marker through the retained owned-root descriptor and rejects, without writing to the foreign replacement.

One intermediate development check failed because the new final-name gate also applied to deliberately deleted private staging directories. The repair scopes that gate to output success: staging removal intentionally has no final-name predicate; restore has its explicit gated marker flow. This preserves the no-overwrite and interrupted-restore acceptance conditions. The new regression verifies both source/root scopes and retained output-anchor lifetime after private stage exit.

Final candidate author verification is now **37 PASS** in 21.70 seconds, exact source hashes unchanged in `verification.json`. It includes the two actual native Linux launcher cases plus executed transient-parent, ordinary-root replacement, reserved-output replacement, non-LIFO anchor lifetime, permanent-output-name, and late-marker-unlink regressions. Earlier 34-case results are preserved in `verification-before-final-binding-repair.json`. Independent review remains a separate receipt; no Windows work was performed.

A final author-owned input-name probe reproduced a late cleanup-ordering problem before repair: renaming the backup input during final marker unlink caused the outer input scope's final name check to reject after marker removal (`restore-input-name-before-repair.json`, hook executed, restored DB present, marker absent). Restore must perform both input/output name checks inside the marker-preservation flow, rather than leaving an input name predicate until scope cleanup after that flow. The held input descriptor continues to bind every source read; disabling that redundant scope-exit predicate does not admit different source bytes.

The final input/output marker-ordering successor now has **38 PASS** (including both actual native Linux recovery cases), source hashes unchanged in `verification.json`. The 37-case precursor receipt is retained as `verification-before-input-marker-ordering-repair.json`. Review scope remains Linux only; independent final closure belongs to the separate reviewer.
