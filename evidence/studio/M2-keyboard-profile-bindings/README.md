## Resulting behavior and actual witnesses

Discovery distinguishes loading, available and unavailable. Failed, malformed,
duplicate or incomplete responses leave availability unknown and offer an abortable
retry; a well-formed empty response states only what that request returned. Associated
guidance explains the additive one to 16 profile selection, exact immutable identities,
unchanged existing locks and edits made while a request is pending. Native retry
loads the actual registry and restores focus while the origin remains current.

Binding freezes the submitted project/revision, exact lock identities, selection
generation and focus origin. Repeated Enter while pending produces exactly one
actual transaction. Checkboxes remain editable. The authoritative returned Project
uses the existing current-project/load/newer-head guard. A current successful request
returns to Workspace, preserves the existing exact success notice and restores XDL
source focus. A newer checkbox choice or deliberately moved focus keeps Environment
open and retains its selection, with a receipt only for the submitted locks.

Held actual HTTP 200 responses verify departed Home receives no stale success notice.
The canonical transaction still commits one revision and exactly one new Profile
resource, preserving complete original document objects, supporting files and existing
locks. New schema/presentation sidecars match admitted digests; authoritative validation,
compiled plan identity, provider discovery and project run sets remain consistent.
This unchanged executable identity follows the selected pure presentation profiles;
it is not a general claim that semantic profiles never affect compilation.

Other held replies preserve a reopened newer revision, exact graph history and a real
ready preflight ID/snapshot. Actual HTTP 412 current and departed refusals are produced
by a public-API writer; selection/current error focus and explicit load-current recovery
are retained, with no unintended transaction. A foreign-project recovery uses only a
newly owned source fixture, restored in finally; while its actual committed reply is
held, a newer Environment checkbox draft stays active, focused and unsubmitted.
The backend recovery still commits independently. Profile interaction advances only
the shared authoring interaction sequence, preserving its own acknowledgement guards.

HTTP 503, missing digest, duplicate and empty discovery responses are explicitly
controlled transport observations. The negative cases perform zero binding writes,
preserve revision/documents/locks and retry the actual registry where offered. Empty
fixture data is never evidence that the actual registry lacks profiles.
