# Reported trace claim metadata, annotation component

FR-062's literal gap was identified before implementation in the parent/child design messages: existing trace targets accepted only `uri` and `revision`, rejecting supplied claim status; frozen assertions had no sidecar association. The first newly written regression invocation against that source produced 3 failed and 15 passed, including refusal of the new status/definition subject requests. This note transcribes those prior observations after implementation and is not an independent review receipt.

The backward-compatible representation is optional `target.claimStatus`: exact reported nonblank string, at most 256 Unicode characters, no control characters. It is opaque external metadata; there is no status enum, default, normalization, proof, or verdict conversion. An omitted legacy claim remains omitted. Existing records are not migrated or rewritten, and old history entries gain no synthetic fields.

Optional annotation `definitionRefs` is a bounded list of exact `{definitionRef, definitionDigest}` subjects from the associated run's frozen input definitions. Model/scenario subjects remain `elementRefs`; canonical run evidence remains `evidenceRefs`. Subject checks share the immutable run snapshot, validate its digest, and reject wrong IDs/digests, current-draft reinterpretation and foreign run subjects. Empty new subject lists are omitted from the stored content; replacement omission clears current definition associations while preserving old revision history. Updates and tombstones retain expected-revision checks.

The existing run export/import preserves these revisioned annotation records exactly as inert data. No evaluator AST, v1 assessment schema bytes, Profile resource version, schema ID, profile-lock format, frozen source input, compiled plan, or canonical journal was changed. No external reference is fetched. A future authored assessment schema extension would require a new schema ID/file/version and multi-version admission dispatch; it must not overwrite the pinned v1 schema. The existing run-scoped sidecar satisfies these associations without that change.

`backend-verification.json` records 29 actual passes (31 unrelated cases deselected), source hashes before/after, exact command, Python and Linux identities. It includes three actual owned reference executions: frozen-subject claim roundtrip across two distinct runs and an actual failed assertion whose verdict stays failed despite a reported external pass. Legacy and new annotation records roundtrip with revisions/tombstones; invalid status types/length/control characters and wrong subject identities refuse; snapshot/plan/journal bytes remain unchanged. Original v1 schema/evaluator/source resolver bytes were captured unchanged. Full `advanced.py` is shared with root; the receipt hashes only its owned annotation block, likewise Annotation models. Separate independent review, frontend workflow verification, full-candidate verification and Windows acceptance remain root-owned. No Windows tests or hardware were used, and no commits were made by this owner.

Before repairing the subject integrity boundary, the owner ran `rehashed_snapshot_probe.py`: after an actual owned reference execution, SQL snapshot metadata was replaced only in the disposable fixture with a different assertion definition and recomputed self-digest. The immutable snapshot file stayed unchanged and did not contain that definition. Both a model subject and the forged definition subject were accepted (201), demonstrating that checking only the metadata's self-digest does not establish original frozen-file identity. This is owner-confirmed evidence, not an independent review claim. `rehashed-snapshot-before-repair.json` retains the observation before the new guard.

The repaired model/definition subject gate now reuses `Runs.verify_snapshot(snapshot)` after self-digest validation, proving exact equality with the bounded, safely acquired original snapshot file. It is intentionally required only for nonempty model or definition subjects. Legacy comments, unscoped reported trace metadata and evidence identifiers remain usable when source files are unavailable; no historical source is regenerated. The expanded existing HTTP case rejects both rehashed metadata-only model/definition associations and missing-source model subjects, while preserving those inert legacy paths. Final focused verification remains **29 PASS**, now in 20.16 seconds, with owned source hashes unchanged; the previous self-digest-only receipt is retained separately. Separate root readiness review covers the shared verifier dependency and full candidate verification remains root-owned.
