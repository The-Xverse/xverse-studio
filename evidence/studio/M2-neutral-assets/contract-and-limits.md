# Neutral logical asset edit contract

Existing authenticated, CSRF-protected `POST /api/v1/projects/{projectId}/edits` is used with `If-Match` and `baseRevision`. Each edit supplies an explicit System `documentId`, `assetKind` (`device`, `sensor`, `actuator`, `model`), immutable `elementId`, and `properties` containing the actual public XDL fields excluding `id`.

- `add_logical_asset` creates one existing System collection member. Optional `endpoints` (maximum 64) is permitted only for a Device, and every endpoint must be owned by that newly created logical Device. Declared interfaces and valid endpoint fields are checked by public XDL validation.
- `update_logical_asset` merges supplied properties into an existing asset of the selected kind. It never renames identity. Optional `elementRef` must identify the selected System/asset. Omitted fields remain intact; null is not a delete instruction.
- Devices use `capabilities`, `supportedRealizationClasses`, optional logical containing `nodeId`, optional admitted `extensions`. Supported realization capability is independent from actual Deployment realization and host placement.
- Sensors use `observedQuantity`, `outputEndpointId`, `unitSemantics`, `maturity`; optional `deviceId`, `samplingIntent`. Actuators use `controlledQuantity`, `inputEndpointId`, `unitSemantics`; optional `deviceId`, `limits`.
- Models use `modelKind`, inert `externalRef`, `inputs`, `outputs`, `maturity`; optional `limitations`. Inputs and outputs are **interface IDs**, as checked by the pinned public semantic validator, not endpoint IDs. No referenced artifact is fetched or executed.
- Sensor output and actuator input choices require compatible declared endpoint directions. Model interface membership remains a public-validator decision. Maturity values are `observed`, `inferred`, `architectural-target`, `prototype`, `verified`.

All edits form one in-memory transaction before serialization/public full-set validation and project commit. Invalid shapes, references, identity collisions or unsupported fields leave the original source/revision intact. Resource-qualified identity is `xdl://{namespace}/system/{name}#{elementId}`. Existing unknown property values allowed by the public schema are preserved (e.g. actuator limits); unsupported/unresolved extensions retain source editing and cannot be silently promoted. Ruamel preserves supported comments and untouched document bytes; changed-document formatting is not asserted byte-identical.

Expected errors include INVALID_EDIT, IDENTITY_CONFLICT, SELECTION_UNRESOLVED, ENDPOINT_UNRESOLVED, ENDPOINT_INCOMPATIBLE and MODEL_INVALID with original public diagnostic codes. No device access, build, flashing, provider start or installation occurs. Additional topology remains outside `studio.reference` executable admission. Linux tests cover this slice; Windows installation/testing remains blocked at user request. This does not complete all T049/T051/T052 or AC-015 requirements.

Review successor: `update_logical_asset` supports explicit `unsetProperties` for schema-optional fields only: Device `nodeId`/`extensions`, Sensor `deviceId`/`samplingIntent`, Actuator `deviceId`/`limits`, Model `limitations`. Use `properties: {}` with `unsetProperties: ["nodeId"]` to leave a placed logical Device unplaced. Required properties and `id` cannot be removed, duplicate unset fields and simultaneous set/unset are rejected. This preserves the separation between logical role, supported realization capability and placement.

Baseline association boundary: public `semantics.py` checks Sensor/Actuator `deviceId` against declared Devices and their endpoint references independently against declared Endpoints. It does not require endpoint.ownerId to equal deviceId. The Studio helper preserves that admitted contract rather than inventing an ownership equality rule; actual physical association, provider admission and permits remain separate gates. Model inputs/outputs are interface IDs (public semantics lines 370–374). No implementation source in the companion repository was changed.
